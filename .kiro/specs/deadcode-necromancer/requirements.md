# Requirements Document: DeadCode Necromancer

## Introduction
DeadCode Necromancer transforms decaying, bug-ridden legacy code into clean, production-grade TypeScript through automated static autopsy, interactive 2D SVG dependency topology, and surgical patch resurrection.

## Requirements

### Requirement 1: Real-Time Curse Autopsy Scanner
- WHEN the user pastes code or selects a haunted legacy preset, THE SYSTEM SHALL scan the source line-by-line for security, concurrency, type-safety, and dead-code curses.
- THE SYSTEM SHALL compute a deterministic Vitality Score (0–100%), Cyclomatic Complexity, and Curse Density.

### Requirement 2: Interactive 2D SVG Call & Taint Topology
- WHEN an autopsy completes, THE SYSTEM SHALL render a crisp 2D SVG topology graph of functions, data sources, and cursed sinks.
- WHEN the user clicks any node in the SVG graph, THE SYSTEM SHALL highlight and scroll to the corresponding line in the code editor.

### Requirement 3: Surgical Resurrection & Live Diff View
- WHEN the user clicks "Cast Resurrection" or exorcises an individual curse, THE SYSTEM SHALL apply deterministic AST/pattern patches to modernize the code (`var` → `const`, `==` → `===`, parameterized SQL, `async/await` refactor, XSS sanitization).
- THE SYSTEM SHALL provide a line-by-line Diff View comparing the original dead code and resurrected output.

### Requirement 4: Kiro Spec & Hook Compliance Telemetry
- THE SYSTEM SHALL evaluate resurrected code against `.kiro/` policy hooks (`zero-eval-policy`, `strict-equality-guard`, `sql-parameterization`, `xss-sink-shield`, `modern-async-flow`) and display real-time pass/fail status.
